## Effort và giới hạn

Các effort là bounded person-day estimates, confidence thấp-vừa; giả định engineer có source/artifact access, reviewer nội bộ và isolated env sẵn. Không gồm vendor response, procurement, approval wait, production handling hoặc remediation tổng. Breakdown: CloudDM public artifact/source/license/counter-path preflight complete; no actual person-day effort recorded and no repeat survey planned. No runtime probe is scheduled for unchanged v4.3.0 because the default compile gate is off; if a supported delta appears, size the regression against that concrete change. CI+Flyway design feasibility inventory/target mapping 1–2 + artifact/approval/per-target result and stop/reconcile workflow 1–2 + maintenance review 1 (total 3–5, low-confidence expert estimate, no implementation; distinct from the historical 20–40 PD operationalization estimate (which includes its initial 5–10 PD POC and assumes existing CI/IDP/Git/secrets/infra); add 15–30 PD for thin control UI/API if absent, combined 35–70 PD; infrastructure setup additional); ODC source/path full-package original estimate 2–4 is not recorded actual effort and is not a new scheduled task; ODC focused regression setup 0.5–1 + cases 1.5–3 PD (total 2–4, conditional on a concrete delta).

Expert engineering scope ranges, not spend or approved budget: CloudDM native **20–50+ PD**; CloudDM workflow + sole Flyway executor adapter **10–25 PD**; ODC governance + sole Flyway adapter **15–35 PD**; thin central inventory+CI+Flyway broader POC **5–10 PD**, operationalization **20–40 PD** assuming CI/IDP/Git/secrets/infra already exist. The **3–5 PD** composition item is feasibility/design only, not the POC. All low confidence, non-additive, excluding production rollout, procurement/wait, full Oracle certification and recurring maintenance. 2–3 release DBA baseline, Oracle versions, CI foundation and maintenance owner will narrow these ranges; missing values do not block completion of public research. Target ledger/recovery implementation remains a large uncertain component. Feasibility phải ghi dependencies, smallest acceptance, effort/confidence, proposed maintenance owner và recurring work (Oracle driver/image compatibility, version regression, catalog, audit export/backup, incident reconciliation/upgrades). Owner/capacity là giả định cần xác nhận, không cam kết của user. Nếu chưa thu hẹp được trong timebox, giữ range unresolved với câu hỏi tiếp/stop decision; không bịa total cost hoặc gán `UNKNOWN` cho toàn bộ.
